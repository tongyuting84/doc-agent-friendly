# 控制台任务 Agent 调用规范

规范版本：v1.0

适用范围：AI Agent 依据火山引擎控制台操作文档执行资源查询、创建、配置、更新、验证和清理任务。

目标：在尽量不改造原操作文档的前提下，由 Agent 从文档步骤中动态识别任务参数，执行前一次性完成输入收集和确认，执行后依据真实终态验收。

关联规范：

- 《全局 Agent 执行规范》：身份、权限、风险、幂等、验证和证据的全局规则。
- 《通用 API Agent 调用规范》：需要通过 API、SDK 或 CLI 辅助查询和验证时适用。
- 本规范：定义控制台任务特有的文档解析、交互表单、浏览器会话、敏感输入和分层验收规则。

## 1. 使用方式

控制台操作文档可以通过极简入口引用本规范：

~~~markdown
> Agent 执行入口：执行本文操作前，请先读取《控制台任务 Agent 调用规范》。Agent 应先根据本文步骤生成任务参数表，完成预检查和一次性确认后再执行。
~~~

本规范不维护各产品的固定参数全集。具体任务需要哪些参数，由 Agent 根据当前文档、当前控制台表单和只读查询结果动态识别。

## 2. 标准执行流程

Agent 必须按照以下顺序执行：

~~~text
完整读取文档
→ 识别步骤、输入、依赖和副作用
→ 生成任务专属参数表
→ 自动发现候选值和默认值
→ 一次性收集用户决策
→ 只读预检查
→ 输出最终执行确认单
→ 获得必要批准
→ 执行控制台操作
→ 查询真实终态
→ 分层验收
→ 输出资源台账、遗留问题和清理状态
~~~

正式执行开始后，Agent 不应再询问可以在执行前识别的问题。只有出现文档外冲突、权限阻塞、库存变化、高风险确认或不可安全推导的异常时才允许中断。

## 3. 从文档动态提取参数

### 3.1 提取对象

Agent 必须完整读取文档，并逐步识别：

1. 每一步需要用户输入、选择或确认的字段；
2. 前置资源、权限、登录状态、地域、项目和配额；
3. 文档示例值、推荐值和默认值；
4. 会创建、修改、删除或复用的资源；
5. 会改变费用、公网暴露、权限和数据范围的选项；
6. 密码、密钥、令牌等敏感输入；
7. 异步步骤、成功状态、失败状态和观察窗口；
8. 清理任务需要的资源标识和依赖关系。

### 3.2 参数分类

每个参数必须归入以下一种类型：

| 类型 | 含义 | 处理规则 |
| --- | --- | --- |
| user_required | 只有用户能决定的业务意图 | 执行前询问，不得猜测 |
| discoverable | 可从控制台或只读接口获得 | Agent 自动查询并记录来源 |
| document_default | 文档明确给出的默认值 | 可以采用，但影响费用或安全时仍须确认 |
| derived | 可由其他输入确定 | Agent 计算并展示推导结果 |
| conditional | 只在特定分支必填 | 仅在条件成立时收集 |
| sensitive | 密码、私钥、Token 等秘密 | 按第 6 节处理 |

### 3.3 禁止把示例当事实

文档中的示例名称、资源 ID、地域、规格、版本和密码不得直接视为用户环境中的真实值。

- “最新版本”必须解析为当前控制台实际可选的最高稳定版本，并在确认单中写明具体版本。
- 示例 VPC、子网、安全组和密钥对必须通过只读查询匹配真实资源。
- 无法唯一匹配时，必须让用户选择。
- 不得默认使用控制台当前选中的资源，因为该默认值可能来自其他业务。

## 4. 任务专属输入表单

### 4.1 生成规则

Agent 应根据当前任务动态生成输入表单，而不是机械套用固定字段。表单应满足：

- 只询问无法安全发现或必须由用户决定的参数；
- 可发现参数优先转换为候选项；
- 对推荐值说明来源；
- 标明必填、条件必填、费用影响、安全影响和敏感字段；
- 关联字段联动显示，例如选择“立即创建节点池”后才出现节点规格、数量和登录方式；
- 用户可以一次提交全部业务选择。

### 4.2 表单按钮语义

初始表单的提交按钮应使用“检查配置”“生成执行方案”或“继续”，不得直接使用“确认创建”。

只有完成环境发现、库存与配额检查、费用识别和资源解析后，最终确认单才可以提供“确认并执行”。

### 4.3 参数来源记录

Agent 应在内部保留脱敏参数快照：

~~~yaml
task_inputs:
  region:
    value: cn-beijing
    source: user
  kubernetes_version:
    value: v1.36.1-vke.7
    source: console_discovery
  project:
    value: default
    source: console_current_context
    confirmation_required: true
~~~

快照不得包含密码、令牌、AK、SK 或私钥。

## 5. 只读预检查

执行有副作用的控制台操作前，至少检查：

1. 浏览器是否已登录正确账号；
2. 地域和项目是否与用户选择一致；
3. 目标资源是否属于预期账号和项目；
4. 依赖资源是否存在且状态可用；
5. 配额、库存、余额和服务授权；
6. 资源名称是否冲突；
7. 文档推荐值是否仍被当前产品支持；
8. 公网访问、权限和安全组带来的暴露范围；
9. 预计创建的收费资源；
10. 是否具备终态查询和清理能力。

预检查失败时不得提交变更。资源状态在确认后发生实质变化时，应重新检查受影响项。

## 6. 敏感信息与测试凭证

### 6.1 通用规则

- 不得要求用户在普通聊天中发送密码、AK、SK、私钥或会话令牌。
- 优先复用已登录的浏览器会话、已有 SSH 密钥对、临时身份或受信任凭证配置。
- 不得从浏览器导出 Cookie、Token 或登录凭证供其他客户端使用。
- 不得将秘密写入代码库、普通文档、执行报告、命令参数或日志。

### 6.2 自动生成一次性测试密码

对于用户明确标记为测试、临时使用的资源，输入表单可以提供“自动生成一次性测试密码”选项。

用户选择后，Agent 应：

1. 生成满足目标产品密码规则的随机强密码；
2. 每次生成不同的密码，不得使用 admin@1234 等固定或弱密码；
3. 直接填写到目标控制台的密码和确认密码字段；
4. 不在普通对话、截图、工具日志和执行报告中回显；
5. 在创建前让用户选择密码交付方式；
6. 测试结束时提醒修改密码或删除资源。

推荐最低要求：长度不少于 12 位，并包含大写字母、小写字母、数字和特殊字符。产品规则更严格时以产品规则为准。

### 6.3 密码交付方式

如果用户后续需要使用自动生成的密码，执行前必须选择以下一种交付方式：

1. 通过支持遮罩、复制和一次性显示的敏感结果字段交付；
2. 保存到用户指定的安全凭证存储；
3. 保存到非仓库临时目录中的本机文件，权限限制为仅当前用户可读写；
4. 用户明确表示无需登录，执行结束后销毁密码。

不得在未提供取回方式时销毁用户后续必需的密码，也不得默认在普通聊天中输出明文。

若采用本机临时文件，最终回复只提供文件路径、权限和清理提醒，不展示密码内容。

### 6.4 生产环境限制

自动生成测试密码只适用于用户明确选择的测试资源。生产、长期运行、共享资源或直接开放公网登录的节点，必须使用组织批准的凭证方式，不得使用测试密码策略。

## 7. 最终执行确认单

### 7.1 确认时机

确认必须发生在所有可发现参数已经解析、预检查完成之后，并且紧邻第一个有副作用的提交动作。

### 7.2 必须展示的内容

确认单至少包含：

- 目标账号、地域和项目；
- 将创建、修改、删除和复用的资源；
- 资源名称、数量、规格、版本和计费方式；
- 公网暴露、权限变化和不可逆风险；
- 控制台当前可见费用及未包含的潜在费用；
- 敏感输入的处理和交付方式；
- 验收条件、最大等待时间和失败处理；
- 清理范围及是否自动清理。

推荐结构：

~~~yaml
execution_confirmation:
  target:
    account: current-console-account
    region: cn-beijing
    project: default
  create:
    - type: vke_cluster
      count: 1
    - type: ecs_node
      count: 1
  reuse:
    - vpc-doc-demo
    - Subnet-a
    - Subnet-b
  security_effects:
    api_server_public_access: true
  cost_effects:
    console_estimate: 0.6727 CNY/hour
    excluded_possible_items:
      - NAT
      - EIP
      - load_balancer
  credential:
    method: generated_test_password
    delivery: one_time_sensitive_display
  acceptance:
    cluster_phase: Running
    ready_nodes: 1
~~~

### 7.3 批准范围

用户批准只对确认单中的账号、地域、项目、资源、参数和时间窗口有效。出现以下情况必须重新确认：

- 新增确认单中没有的收费资源；
- 扩大公网暴露或权限；
- 规格、数量或计费方式发生变化；
- 需要删除已有资源；
- 目标账号、地域、项目或资源发生变化。

## 8. 控制台执行规则

- 优先使用语义明确的字段、按钮和状态，不依赖易变化的坐标。
- 每完成一个步骤，读取页面最新状态后再决定下一步。
- 不得把“按钮已点击”视为操作成功。
- 遇到页面刷新、会话中断或超时，不得直接重新创建；先按名称、任务 ID 或资源 ID 查询是否已生效。
- 页面提示和文档描述不一致时，以真实资源状态和服务端结果为准，并记录差异。
- 用户已填写的敏感字段不得读取、复制或回显，只检查是否已填写。

## 9. 异步任务、轮询与超时

控制台提示“提交成功”或“创建成功”不代表整个任务完成。Agent 必须分别观察：

1. 控制面或主资源创建任务；
2. 子资源或节点池任务；
3. 实例或节点就绪状态；
4. 必装组件状态；
5. 文档要求的业务可用性。

任务文档提供等待时间时优先采用；未提供时，Agent 应根据产品状态设置合理观察窗口，并在最终结果中记录实际耗时。

长时间无变化时，应查询创建过程、任务记录、事件和组件部署详情。不得仅因进度暂时不动就重复提交。

## 10. 分层验收

### 10.1 最低验收原则

任务完成必须同时满足任务目标和文档定义的真实终态。对于创建集群类任务，推荐分层验收：

~~~yaml
acceptance:
  resource:
    cluster_phase: Running
  capacity:
    node_pool_phase: Running
    ready_nodes: expected_nodes
  platform:
    required_addons: healthy
  optional:
    optional_addon_failure_policy: warn
~~~

### 10.2 必装与可选组件

- 必装组件异常可能影响主体任务，应继续观察或判定失败。
- 可选观测、日志等组件异常时，可以将主体任务判定为成功，但必须明确输出告警、影响范围和处理建议。
- “降级可用”不得直接等同于完全健康，应说明降级原因和是否符合任务验收标准。

### 10.3 成功状态

- verified_success：目标资源及全部必要验收条件通过。
- verified_success_with_warnings：主体资源可用，但存在不阻塞目标的可选组件或观测告警。
- safe_blocked：缺少输入、授权、依赖或确认，已安全停止。
- failure：执行失败、必要验收失败或超过观察窗口。

## 11. 资源台账与清理

创建完成后必须输出脱敏资源台账，至少包含：

- 主资源和子资源的名称、类型和 ID；
- 地域、项目和计费方式；
- 自动创建的网络、存储、安全和公网资源；
- 资源之间的依赖关系；
- 删除保护状态；
- 当前清理状态。

删除主资源不一定会删除 ECS、云盘、NAT、EIP、负载均衡和安全组。清理必须逐项核对，不得根据名称模糊匹配删除，也不得自动删除用户原有资源。

## 12. 最终回复要求

最终回复必须包含：

1. 标准任务状态；
2. 实际完成的操作；
3. 主资源和关键子资源 ID；
4. 每层验收结果；
5. 当前费用和持续计费提醒；
6. 公网暴露及其他安全影响；
7. 敏感凭证的取回位置或处置结果，不得包含明文；
8. 异常、降级状态和影响；
9. 清理状态与后续操作。

不得使用“应该成功”“看起来正常”等表述代替真实验收。

## 13. VKE 创建集群示例

Agent 读取创建 VKE 集群文档后，应动态识别并收集：地域、项目、集群名称、Kubernetes 版本策略、VPC、控制面子网、Pod 子网、网络模型、公网访问、API Server 公网访问、节点池选择、节点规格、数量、云盘、登录方式、组件和清理意图。

其中：

- Kubernetes 具体版本、可用 VPC、子网、规格库存和配额应自动发现；
- 是否开放公网、节点数量、计费方式和登录方式必须由用户决定或确认；
- 文档示例名称不得直接用于共享账号；
- 自动生成测试密码只可在用户明确选择后使用；
- 最低验收应包括集群 Running、节点池 Running 和节点 Ready；
- 默认观测组件异常可以作为告警，但必须说明是否影响任务目标；
- 最终台账应包含集群、节点池、ECS、云盘、NAT、EIP、负载均衡和安全组。
