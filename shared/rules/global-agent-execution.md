# 全局 Agent 执行规范

> 本规范是所有 Agent 可执行文档的统一入口。业务文档原则上只需引用本规范；Agent 必须先读取本规范，再根据文档中的实际操作类型加载对应子规范。

## 1. 适用范围与职责

本规范适用于 API、SDK、API Explorer、云控制台和 Kubernetes YAML 操作。它只定义跨产品、跨执行渠道通用的规则：目标与完成条件、动态输入、禁止猜测、只读预检查、风险与确认、幂等与重试、异步观察、真实验收、证据、清理和规范路由。

产品事实、业务参数、操作步骤和产品特有成功条件以当前业务文档为准；接口参数以当前 API 文档为准；平台 IAM、服务端校验和审批策略始终优先。

## 2. 子规范加载规则

Agent 在修改外部环境前，必须完整读取当前业务文档，识别其中所有操作类型，并读取对应子规范。链接是强制执行依赖，不是可选参考资料。

| 识别信号 | 操作类型 | 必须继续读取 |
| --- | --- | --- |
| API Action、Version、Endpoint、请求参数、SDK 示例、API Explorer、签名 HTTP | API | [API Agent 调用规范](api-agent-invocation.md)和[Agent API 凭证配置指南](api-credential-configuration.md) |
| 控制台页面、按钮、表单、向导、浏览器登录态 | 控制台 | [控制台 Agent 操作规范](console-agent-operation.md) |
| Kubernetes YAML、`apiVersion`、`kind`、`kubectl` | Kubernetes YAML | [Kubernetes YAML Agent 执行规范](kubernetes-yaml-agent-execution.md) |

路由要求：

1. 一篇文档包含多种操作时，加载全部相关子规范，并按操作阶段分别执行。
2. API Explorer 也属于 API 操作；凭证指南用于判断浏览器会话认证边界。
3. SDK 或签名 HTTP 不得省略凭证指南。
4. 控制台任务中出现 YAML 时，同时读取控制台规范和 Kubernetes YAML 规范。
5. 未完成所需子规范读取前，不得开始有副作用的操作。
6. 无法确定操作类型时返回 `safe_blocked`，不得选择最相似的渠道继续执行。

业务文档推荐只保留一个入口：

```markdown
> AI Agent 执行入口：执行本文操作前，请先读取并遵守[《全局 Agent 执行规范》](<公开可访问的规范地址>)。该规范会根据本文操作类型加载必要的子规范。
```

## 3. 规则优先级

发生冲突时，优先级从高到低为：

1. 平台安全策略、IAM、服务端校验和审批机制；
2. 用户对本次任务的明确授权；
3. 当前业务文档中的产品事实、限制和验收要求；
4. 本规范及其路由到的子规范；
5. 文档示例、界面默认值和工具默认值。

示例值不能替代真实参数，文档不能扩大用户权限。

## 4. 标准执行流程

```text
完整读取业务文档
→ 识别目标、完成条件和操作类型
→ 加载全部适用子规范
→ 提取输入、依赖、风险和副作用
→ 自动发现可安全确定的信息
→ 一次性收集用户决策
→ 只读预检查
→ 输出最终执行确认单
→ 获得必要批准
→ 执行确定性操作
→ 观察异步过程并查询真实终态
→ 验证业务结果
→ 输出脱敏证据、资源台账和清理状态
```

不得因为 HTTP 成功、按钮已点击、命令退出码为 0 或资源 ID 已返回就宣布任务完成。

## 5. 任务输入清单、输入收集与禁止猜测

Agent 应从当前业务文档动态提取输入，而不是维护所有产品的固定参数表，也不要求每篇业务文档重复提供统一格式的“执行前参数清单”。业务文档负责给出产品特有的参数含义、来源、约束、默认值和使用位置；本规范负责要求 Agent 将这些事实整理成本次任务的输入清单。

Agent 必须先完整读取业务文档、适用子规范及其明确依赖，扫描全部步骤和条件分支，再生成结构化的“本次任务输入清单”。清单生成完成前，不得开始逐项询问用户，也不得执行有副作用的操作。

| 输入类型 | 处理规则 |
| --- | --- |
| `user_required` | 只有用户能决定的业务目标、范围、成本或安全选择；执行前询问 |
| `discoverable` | 可通过已授权环境或只读查询获得；自动发现并记录来源 |
| `document_default` | 文档明确给出的默认值；影响费用或安全时仍须确认 |
| `derived` | 可由已确认输入确定；计算并展示推导结果 |
| `conditional` | 仅在对应分支成立时收集 |
| `sensitive` | 使用受控输入或凭证机制，不得要求粘贴到普通聊天 |

任务输入清单至少记录：

| 字段 | 要求 |
| --- | --- |
| 参数或资源 | 使用业务文档中的真实名称，区分 Name、ID、Key、凭证和资源对象 |
| 含义与约束 | 记录类型、合法值、地域/账号/资源绑定及产品限制 |
| 来源 | 标明业务文档、子规范、只读查询、上一步输出或用户选择 |
| 输入类型 | 标记为 `user_required`、`discoverable`、`document_default`、`derived`、`conditional` 或 `sensitive` |
| 当前值或候选项 | 记录已发现值；多个候选项不得擅自选择，应脱敏展示供用户决定 |
| 使用位置 | 标明在哪个步骤、请求字段、页面表单或配置项中使用 |
| 费用与安全影响 | 标明是否影响计费、公网暴露、权限、删除或生产环境 |
| 确认状态 | 标记已确定、待用户选择、待安全输入或缺少产品事实 |

先通过已授权的只读能力自动发现 `discoverable` 输入，并记录查询来源。只向用户一次性展示和收集以下内容：

1. `user_required` 的真实业务选择；
2. 无法唯一确定的候选项；
3. 尚未通过安全机制提供的 `sensitive` 输入；
4. 影响费用、安全、权限、删除或公网暴露的 `document_default` 和 `derived` 结果；
5. 因业务文档缺少产品事实而无法确定的项目，此时应明确报告文档缺口，不得把未知事实伪装成普通用户参数。

不得猜测账号、地域、项目、环境、资源归属、资源 ID、集群、网络、镜像、规格、凭证、身份、权限、计费方式、预算、生产变更窗口、成功条件和清理范围。存在多个候选项且无法唯一确定时，必须让用户选择。正式执行开始后，不应再询问能够在执行前识别的问题；若执行中出现文档无法预见的新条件，应暂停、更新输入清单和确认单，并仅对新增范围请求补充确认。

## 6. 敏感信息原则

- 不得要求用户在普通聊天中发送 AK、SK、SessionToken、密码、私钥或 Cookie。
- 不得把秘密写入源码、Markdown、命令参数、日志、截图、Git 仓库或最终回复。
- 只能检查敏感输入是否已配置，不得回显其值。
- 不得导出浏览器 Cookie 或令牌供 SDK、命令行或其他客户端使用。
- API 认证的详细处理遵守[Agent API 凭证配置指南](api-credential-configuration.md)。
- 控制台密码生成与交付遵守[控制台 Agent 操作规范](console-agent-operation.md)。

## 7. 风险、预检查与批准

| 风险 | 示例 | 默认策略 |
| --- | --- | --- |
| R0 本地只读 | 读取文档、检查工具版本、校验本地文件 | 可直接执行 |
| R1 云端只读 | 查询资源、状态、权限和配置 | 可直接执行并脱敏记录 |
| R2 可恢复变更 | 创建测试资源、更新配置、应用可回滚 YAML | 展示计划并按授权确认 |
| R3 高影响或难恢复 | 删除生产资源、扩大公网暴露、权限提升、长期付费购买 | 必须单独明确确认 |

有副作用的操作前至少检查当前身份与目标环境、权限与依赖、参数与兼容性、配额库存与费用、重复或部分生效状态、安全影响，以及是否具备终态查询和清理能力。

最终确认单至少包含目标环境、创建/修改/删除/复用对象、关键参数、费用和安全影响、验收条件、等待时间及清理范围。批准只覆盖确认单中的范围；范围扩大时必须重新确认。

## 8. 确定性执行、幂等与重试

- 使用稳定标识，不得根据名称模糊匹配修改或删除资源。
- 支持幂等令牌时，同一执行意图重试复用原令牌；新意图使用新令牌。
- 写操作超时后先查询是否已生效，不能直接重复提交。
- 只有明确的限流、临时网络故障、临时服务不可用或文档声明可重试的错误可以有限重试。
- 权限、认证、参数、配额、库存、资源冲突和结果不确定不得盲目重试。
- 不得为了成功而切换到权限更高的身份或扩大操作范围。

## 9. 异步观察与真实验收

Agent 必须使用业务文档或适用子规范指定的查询方式观察进行中、成功和失败状态，并遵守最大观察窗口和业务断言。验收必须独立读取真实终态，不能只依赖提交响应、退出码、页面提示、Mock 或 Agent 总结。缺少终态查询或成功定义时返回 `safe_blocked`。

## 10. 标准结果状态

| 状态 | 含义 | 是否完成 |
| --- | --- | --- |
| `verified_success` | 真实终态和全部必要断言通过 | 是 |
| `verified_success_with_warnings` | 主体目标通过，但存在不阻塞目标的明确告警 | 是，带告警 |
| `safe_blocked` | 缺少输入、授权、依赖、工具或文档语义，已安全停止 | 否 |
| `failure` | 执行失败、必要验收失败或观察超时 | 否 |

## 11. 证据、失败恢复与清理

至少记录业务文档和规范版本、脱敏输入、计划与批准范围、执行渠道、操作/请求/资源 ID、重试、异步状态、终态、验收结果、副作用和清理状态。

失败后停止扩大变更，检查是否部分生效，再依据文档恢复。无法安全恢复时停止并说明人工接管条件。清理只针对本次明确创建且可精确识别的资源，不得自动删除用户原有资源；无法清理的持续计费资源必须提示。

## 12. 最终回复

最终回复必须说明标准任务状态、实际操作和执行渠道、关键 ID、验收结果及告警、费用与安全影响、清理状态、未解决问题和下一步。不得使用“应该成功”“看起来正常”等未验证表述，也不得包含任何秘密。
