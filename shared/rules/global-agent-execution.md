# 全局 Agent 执行规范

规范版本：v1.1 

> 适用范围：面向 AI Agent 执行的火山引擎 API、CLI、SDK 和任务文档 

> 目标：统一身份、权限、计划、执行、验证、失败恢复和证据要求，避免在每篇 API 文档中重复维护。

## 1. 使用方式

任务文档和 API 文档通过版本化引用使用本规范：

```yaml
agent_execution_convention:
  name: volcengine-agent-execution-convention
  version: "1.1"
```

本文只定义跨产品、跨接口通用的执行规则。任务特有的输入、步骤、风险、验收条件和恢复方式由任务文档定义；接口特有的参数、返回值和错误语义由 API 文档定义。

优先级从高到低为：

1. 平台 IAM、服务端校验和审批策略；

1. 当前任务的用户授权；

1. 任务文档中的风险和验收要求；

1. 本规范；

1. API 文档中的默认示例。

文档不能扩大用户权限，也不能替代服务端授权。

## 2. 标准执行流程

Agent 必须按照以下顺序执行任务：

```
理解目标
→ 收集上下文
→ 只读预检查
→ 生成执行计划
→ 获取必要批准
→ 执行确定性操作
→ 查询真实终态
→ 验证业务结果
→ 输出证据
→ 清理样例资源或安全停止
```

Agent 不得跳过预检查和验证，也不得因为 API 返回成功或命令退出码为 0 就宣布任务完成。

## 3. 输入与上下文

### 3.1 输入来源

输入按以下来源分类：

| 类型 | 示例 | 处理规则 |
| --- | --- | --- |
| 用户必须提供 | 业务目标、目标账号、成本上限、是否允许生产变更 | 缺失时询问用户，不得猜测 |
| 可以安全发现 | 当前地域、资源状态、已有资源 ID | 优先使用只读接口查询，并记录来源 |
| 敏感输入 | AK、SK、临时令牌、密码 | 只能由受控凭证机制提供，不得要求粘贴到聊天中 |
| 派生输入 | 幂等令牌、计划摘要、轮询截止时间 | 由 Agent 按文档规则生成并记录 |

### 3.2 禁止猜测

Agent 不得猜测以下内容：

- 账号、地域、项目或资源归属；

- 集群、子网、安全组、镜像等资源 ID；

- 访问密钥、角色和权限；

- 计费方式、预算和购买周期；

- 生产环境变更窗口；

- 文档未定义的成功标准。

### 3.3 输入快照

执行有副作用的任务前，应生成输入快照。快照不得包含密钥和令牌。

```json
{
  "task_id": "create-vke-nodepool",
  "environment": "test",
  "region": "cn-beijing",
  "resource_ids": {
    "cluster_id": "<cluster-id>",
    "subnet_ids": ["<subnet-id>"],
    "security_group_ids": ["<security-group-id>"]
  },
  "constraints": {
    "billing_type": "PostPaid",
    "desired_replicas": 1,
    "public_access": false
  }
}
```

## 4. 身份与凭证

### 4.1 基本规则

- 优先使用短期凭证、角色、工作负载身份或已配置的凭证链。

- 不得将 AK、SK、会话令牌或密码写入源代码、文档、命令参数、日志和最终回复。

- 只检查凭证是否存在，不得输出凭证值。

- 不得切换到权限更高的身份来绕过拒绝。

- 认证失败时，Agent 应停止并说明需要修复的凭证配置

### 4.2 认证与执行环境

执行云 API 前，执行环境必须已经配置有效的身份凭证，并具备目标接口所需权限。

凭证可通过以下任一方式提供：

- 云平台提供的实例角色或工作负载身份。

- 已配置的 CLI Profile。

- 执行环境中的安全凭证变量。

- 用户授权的 API Explorer 登录会话。

- 其他受支持的临时身份凭证。

Agent 不得要求用户在普通对话中直接发送 AccessKey、SecretKey 或会话令牌。

如果执行环境没有可用凭证，Agent 应停止执行，并引导用户在本地或受信任的凭证管理系统中完成配置。配置完成后再继续调用。

### 4.3 最小权限

任务文档必须列出：

- 只读预检查所需权限；

- 执行变更所需权限；

- 验证终态所需权限；

- 清理样例资源所需权限。

权限不足时返回 safe_blocked，不计为任务成功。

## 5. 操作风险分级

| 风险级别 | 类型 | 示例 | 默认策略 |
| --- | --- | --- | --- |
| R0 | 本地只读 | 读取文档、检查工具版本 | 可直接执行 |
| R1 | 云端只读 | 查询集群、镜像、节点池状态 | 可直接执行并记录 RequestId |
| R2 | 可恢复变更 | 创建测试节点池、更新标签 | 先展示计划；按环境和用户授权决定是否批准 |
| R3 | 高影响或可能不可逆 | 删除生产资源、扩大公网暴露、长期付费购买 | 必须获得明确批准并满足平台策略 |

任务文档必须标明整体风险级别。单个步骤风险更高时，以更高风险为准。

## 6. 预检查

执行有副作用的操作前，至少检查：

1. 调用身份和目标账号；

1. 地域与资源归属；

1. 必需权限；

1. 依赖资源状态；

1. 参数格式和资源兼容性；

1. 配额、库存和成本约束；

1. 是否存在同名资源或重复任务；

1. 是否具备终态查询和清理能力。

预检查失败时不得继续执行变更。

## 7. 执行计划与批准

### 7.1 计划内容

计划至少包含：

```json
{
  "operation": "CreateNodePool",
  "risk": "R2",
  "target": {
    "region": "cn-beijing",
    "cluster_id": "<cluster-id>"
  },
  "changes": {
    "create": ["one node pool", "one pay-as-you-go node"],
    "update": [],
    "delete": []
  },
  "cost_effect": "creates billable ECS and storage resources",
  "rollback": "delete the newly created node pool after confirmation",
  "verification": "node pool Running/Ok and requested nodes ready"
}
```

### 7.2 批准规则

- 只读操作不需要变更批准。

- 用户已明确要求创建测试资源，并且计划没有扩大范围时，可以按宿主确认策略执行。

- 生产环境、付费周期、删除、公网暴露或权限变更必须单独确认。

- 批准仅对计划中的资源、地域、参数和时间窗口有效。

- 计划生成后资源状态发生变化时，应重新预检查。

## 8. 幂等与并发

- 支持幂等令牌的创建和变更接口必须使用稳定的 ClientToken。

- 同一执行意图重试时复用原令牌；不同执行意图使用新令牌。

- 不得因网络超时直接重新创建资源，应先按名称、令牌或任务 ID 查询结果。

- 执行前后应记录资源版本、状态或关键配置，防止旧计划覆盖新状态。

幂等令牌不得包含账号、密钥或其他敏感信息。

## 9. 重试、轮询与超时

### 9.1 可以重试

以下错误可以有限重试：

- 明确的限流错误；

- 临时网络故障；

- 服务端临时不可用；

- 文档明确标记为可重试的状态。

默认最多重试 3 次，采用退避间隔，例如 1 秒、2 秒和 4 秒。任务文档可以覆盖该策略。

### 9.2 不得自动重试

- 权限不足；

- 参数校验失败；

- 资源不兼容；

- 配额或预算不足；

- 需要用户选择的冲突；

- 不确定上一次有副作用的请求是否已生效。

### 9.3 异步任务

创建和变更接口返回资源 ID，不代表任务已经完成。Agent 必须轮询查询接口，直到：

- 满足任务文档定义的成功状态；

- 进入明确失败状态；或

- 超过观察窗口。

超时属于 failure 或 safe_blocked，不能宣布成功。

## 10. 验证规则

验证必须独立读取真实终态，不得只使用以下信号：

- 命令退出码为 0；

- HTTP 请求成功提交；

- 创建接口返回资源 ID；

- Agent 自己生成的总结；

- Mock 或静态示例结果。

任务文档必须定义：

- 查询终态使用的接口；

- 成功状态及字段；

- 失败状态及字段；

- 业务断言；

- 观察窗口；

- 必须保存的证据。

Agent 不得自行降低或重定义验收条件。

## 11. 标准结果状态

| 状态 | 含义 | 是否完成 |
| --- | --- | --- |
| verified_success | 真实操作完成，终态和业务断言全部通过 | 是 |
| safe_blocked | 缺少授权、输入、依赖或工具，Agent 已安全停止 | 否 |
| failure | 执行或验证失败，或者观察窗口超时 | 否 |

标准结果结构：

```json
{
  "status": "verified_success",
  "task_id": "<task-id>",
  "operation_ids": ["<request-id>"],
  "resource_ids": ["<resource-id>"],
  "assertions": [
    {
      "name": "<assertion-name>",
      "passed": true,
      "observed": "<sanitized-value>"
    }
  ],
  "side_effects": ["<created-or-changed-resource>"],
  "cleanup_status": "not_requested"
}
```

## 12. 证据与脱敏

每次执行至少保留：

- 文档和任务规范版本；

- 脱敏后的输入快照；

- 执行计划和批准范围；

- API Action、RequestId 和时间；

- 新建或修改的资源 ID；

- 轮询到的终态；

- 每项验收断言及观察值；

- 重试、失败、恢复和清理记录。

不得保留：

- AK、SK、会话令牌、密码；

- 未脱敏的个人信息；

- 与当前任务无关的账号或资源数据。

## 13. 失败恢复

失败后按照以下顺序处理：

1. 停止扩大变更范围。

1. 保存错误码、RequestId、资源 ID 和当前状态。

1. 判断错误是否可重试。

1. 查询有副作用的请求是否已经部分生效。

1. 按任务文档执行补偿或回滚。

1. 无法安全恢复时返回 safe_blocked 或 failure，说明人工接管条件。

不得为了获得成功结果而删除失败证据或修改旧执行记录。

## 14. 清理规则

- 清理只针对本次任务明确创建的样例资源。

- 删除前必须核对资源 ID、创建记录、依赖关系和用户授权。

- 不得根据名称模糊匹配删除资源。

- 不得擅自删除用户原有资源。

- 如果资源正在计费但无法自动清理，应明确提醒用户并给出资源 ID 和清理方法。

清理是独立操作。任务成功不等于已经完成清理。

## 15. Agent 最终回复要求

最终回复必须包含：

1. 任务状态；

1. 实际完成的操作；

1. 真实资源或任务 ID；

1. 验收结果；

1. 产生的费用或其他副作用；

1. 清理状态；

1. 未解决问题和下一步。

不得使用“应该成功”“看起来正常”等无法验证的表述代替验收结果。

## 16. 认证环境隔离与凭证生命周期

### 16.1 不同执行方式的认证相互独立

- API Explorer 使用当前浏览器登录会话；
- SDK 使用本地凭证、配置文件、实例角色或工作负载身份；
- CLI 使用已配置的 CLI Profile 或其他受支持身份；
- 签名 HTTP 客户端使用访问密钥或临时安全凭证。

浏览器已经登录不代表 SDK 或 CLI 已完成认证。Agent 不得从浏览器导出 Cookie、登录凭证、临时令牌或签名信息供其他客户端使用。

### 16.2 凭证来源优先级

凭证来源优先级为：

1. 工作负载身份、实例角色或平台托管身份；
2. 有明确有效期的临时安全凭证；
3. 受信任凭证存储或已配置的 Profile；
4. 仅在无法使用以上方式时，使用长期 AK/SK。

Agent 不得要求用户把 AK、SK、令牌或密码发送到普通聊天。需要人工准备凭证时，应引导用户使用[《Agent API 凭证配置指南》](api-credential-configuration.md)中的本地安全方式。

### 16.3 临时凭证文件

必须使用临时凭证文件时：

- 文件必须位于非仓库临时目录；
- 权限必须限制为仅当前用户可读写；
- 不得把凭证写入命令参数、日志、截图或最终回复；
- Agent 只能检查凭证是否存在和格式是否满足最低要求，不得回显内容；
- 调用结束后，无论成功或失败，都应删除临时凭证文件；
- 删除失败时必须明确告知用户残留路径。

### 16.4 认证失败

认证失败时不得通过切换到权限更高的身份、导出浏览器凭证或重复猜测凭证来规避。Agent 应保存脱敏错误类别和 RequestId，返回 safe_blocked 或 failure，并说明需要修复的认证配置。
