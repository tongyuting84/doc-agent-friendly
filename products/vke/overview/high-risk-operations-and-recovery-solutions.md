# 高危操作及恢复方案

对集群、节点、网络、存储、日志和系统组件的直接修改可能造成业务中断或数据丢失。执行任何高危操作前，应确认资源归属、影响范围、备份、恢复能力和维护窗口。

## 集群、节点池和节点

| 高危操作 | 可能影响 | 恢复原则 |
|---|---|---|
| 修改 API Server 关联的负载均衡及子资源 | 集群 API 不可访问 | 可能无法恢复，不应绕过 VKE 管理 |
| 在节点安装不受支持的容器运行时 | 节点不可用 | 保留 ECS 后移除并重新添加节点 |
| 修改节点默认安全组、IP、核心组件或系统配置 | 节点或网络异常 | 恢复原配置；无法确认时停止并联系支持 |
| 重装系统或变更 ECS 规格 | 节点组件和参数异常 | 保留 ECS 后按 VKE 流程重新初始化节点 |
| 移除节点但不保留 ECS | 节点及相关数据丢失 | 通常不可恢复 |
| 删除节点池 | 节点池内节点被移除 | 通常不可恢复，应事先迁移负载和数据 |
| 删除或修改 VKE 服务角色策略 | 集群功能不可用 | 恢复可信来源定义的角色策略 |

不要在节点系统盘保存唯一的重要业务数据。添加已有节点前应完成数据备份。

## 网络和负载均衡

- 不要通过负载均衡控制台直接修改由 VKE 管理的 CLB、ALB、监听器或服务器组。
- 不要随意修改节点 IP 转发、反向路径过滤、IPVS 或 IPv6 等内核参数。
- 复用已有负载均衡时，修改 Kubernetes Annotation 前应确认资源所有权和解绑影响。

网络参数的恢复值与操作系统、集群网络模型和业务配置有关，必须以对应官网章节和当前环境为准。

## 存储

- 不要在控制台手动卸载仍被 Pod 使用的云盘或文件系统。
- 不要直接操作节点上的云盘挂载路径。
- 删除存储卷、挂载点或后端存储前，应确认数据备份、Pod 使用状态和回收策略。

错误操作可能导致 I/O 错误、挂起或数据写入本地盘，部分情况无法恢复。

## 日志和组件

- 删除日志采集状态目录可能导致日志重复采集。
- 删除日志组件可能造成采集能力中断，期间日志可能无法恢复。
- 不要直接删除或修改托管组件的工作负载、ConfigMap 等资源。
- 非系统必装组件可能通过卸载后重装恢复；系统必装组件不一定可恢复。

## Agent 执行要求

本文仅描述风险，不授权执行高危操作。Agent 必须遵守[全局 Agent 执行规范](../../../shared/rules/global-agent-execution.md)中的风险确认、只读预检查、资源所有权和清理规则；缺少精确恢复方案时应返回 `safe_blocked`。

完整风险项及精确恢复步骤请参见[官网原文](https://docs.volcengine.com/docs/vke/high-risk-operations-and-recovery-solutions?lang=zh)。
